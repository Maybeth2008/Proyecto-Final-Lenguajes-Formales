## Descripción del Proyecto

Este proyecto implementa un pequeño sistema de reglas utilizando Java. El programa permite ingresar variables, hechos y reglas lógicas para generar nuevas conclusiones automáticamente a partir de condiciones definidas por el usuario.
El proyecto incluye:

- Análisis léxico
- Análisis sintáctico
- Construcción de AST
- Interpretación de reglas
- Encadenamiento de hechos
- Análisis estático de reglas

El sistema fue desarrollado siguiendo la gramática y requisitos definidos en el documento.

---

# Características Implementadas

## 1. Análisis Léxico

El analizador léxico reconoce:

### Palabras reservadas

- `rule`
- `if`
- `then`
- `AND`

### Operadores

- `>`
- `<`
- `>=`
- `<=`
- `=`

### Otros elementos

- Identificadores
- Números enteros

---

## 2. Análisis Sintáctico

El parser valida la estructura de las reglas según la gramática definida.

### Ejemplo válido

```txt
rule r1: if temp > 30 then alert
```

---

## 3. Árbol de Sintaxis Abstracta (AST)

Cada regla se almacena en un objeto AST con la siguiente información:

- Nombre de la regla
- Condición
- Acción
- Estado de ejecución

---

## 4. Intérprete

El intérprete permite trabajar con:

### Variables numéricas

```txt
temp=35
humidity=20
```

### Hechos iniciales

```txt
a
```

### Comparaciones

```txt
temp > 30
humidity <= 50
```

### Condiciones AND

```txt
temp > 30 AND humidity < 50
```

### Encadenamiento de reglas

#### Entrada

```txt
rule r1: if a then b
rule r2: if b then c
rule r3: if c then d
```

#### Salida

```txt
b
c
d
```

# Análisis Estático

El sistema incluye un módulo de análisis estático encargado de detectar problemas potenciales en las reglas.

---

## 1. Reglas Redundantes

Detecta reglas con:

- misma condición
- misma acción

### Ejemplo

```txt
rule r1: if temp > 30 then alert
rule r2: if temp > 30 then alert
```

### Salida

```txt
Redundant rules: r1, r2
```

---

## 2. Conflictos

Detecta múltiples reglas que generan la misma acción.

### Ejemplo

```txt
rule r1: if temp > 30 then fan_on
rule r2: if humidity > 60 then fan_on
```

### Salida

```txt
Action fan_on generated by r1, r2
```

---

## 3. Reglas Potencialmente Inactivas

Detecta reglas que no lograron ejecutarse durante la interpretación.

### Ejemplo

```txt
Potentially inactive rule: r3
```

---

# Ordenamiento Lexicográfico

La salida de los hechos generados se ordena automáticamente utilizando `TreeSet`.

### Ejemplo

